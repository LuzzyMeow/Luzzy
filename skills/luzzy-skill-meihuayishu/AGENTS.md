## 0. 你在维护什么

一个梅花易数技能家族（Luzzy 规范 L5）：编排器 `SKILL.md` + 三个子技能 + 零依赖引擎
（`engine.py` / `lunarcal.py`）+ 64 卦索引（`gua_index.json`）+ 内置经典全文
（`references/`）+ 回归评测（`evals/`）。

用户链路：`Agent 识别方式 → 调引擎 → 查内置经文 → 四层解卦并标注出处`。
**引擎负责一切计算，references 负责一切引文，SKILL 只负责流程与路由**——
这个分工是全仓库的设计基轴，增量更新不得打破。

## 1. 硬性规定（红线）

**R1 · 手写原则。** SKILL.md、README、sources.md 等**authored 内容必须手写**，
禁止用脚本生成正文。唯一例外：经典原文照录件允许"机械执行、人工裁决"的精确替换，
但每一处改动必须由人（Agent）逐条裁决并记入校勘记（见 R3）。

**R2 · 经典文本神圣性。** `references/meihua-juan*.md`、`zhouyi-*.md` 是**照录件**，
禁止改写、意译、删节、白话化。只允许三类操作，且必须留痕：
① 径改明显讹字 → 记入文末校勘记；② 补底本脱句 → 正文标〔补〕并记录；
③ 两本异文加〔校注〕或在校勘记存录。除此之外一个字都不能动。

**R3 · 底本与异文纪律。** 《周易》底本 = ctext 武英殿十三经注疏本（`/zhs` 页）；
《梅花易数》底本 = 原通行本 + 维基文库交叉校验。两本不一致时**照录底本、注明异文**，
禁止凭"哪个读起来通顺"择优改字。经典内部的千古异文（遯/遁、巳日/已日、硕鼠/鼫鼠）
一律保持底本原貌。

**R4 · 计算一律走引擎。** 任何起卦计算不得手写进文档或由 Agent 心算得出。
文档中的每个卦例数字（34÷8余2之类）必须与引擎实跑输出一致——`evals/` 的
「SKILL 示例回归」组就是为锁死这一点存在的。

**R5 · 回归门槛（合并前强制）。** 以下三条命令必须全部通过，缺一不可：
```bash
python3 evals/integrity_check.py   # 结构完整性 + 版本一致性（见 §3）
python3 evals/run.py               # 16+ 组回归用例，含原书占例
python3 lunarcal.py --selftest     # 34 项历表锚点
```
评测用例**只能增加，不得删除或放宽断言**；确需删除属破坏性变更，须在提交说明中
给出理由并另行确认。

**R6 · 数据结构冻结。**
- `gua_index.json`：64 项；「爻」= 自下而上 1 阳 0 阴；「卦画」= `chr(0x4DC0+序-1)`；
  上/下卦数 = 先天数；slug 与 ctext 一致。字段可增不可改义、不可删。
- `lunarcal.py`：`LUNAR_INFO` / `STERM_INFO` 各 **201 项**（1900–2100），
  条目损坏按同行模式修复并跑自检；「极早年（1900–1950）锚点较少」的免责声明**不得删除**。
- 家族目录布局冻结：编排器在根，子技能一级目录，资料在 `references/`，评测在 `evals/`。
  部署契约：技能根目录在部分环境挂载为 `/workspace/meihua/`，引擎路径必须按
  `__file__` 自解析（保持跨目录可运行）。

**R7 · Luzzy 合规。** 四个 SKILL.md：`name` 与目录名一致；description 保持
触发词 + **反触发**（不得吞并六爻、八字、学术周易分析）；正文 **≤ 500 行**；
每技能 ≥2 个 I/O 示例 + Verify 清单。

**R8 · 引文纪律。** 解卦引文标注格式：`文件名 + 卦名 + 爻位`；联网取材必须标注
完整 URL；未经双源验证的文字不得作为经文引用；两源冲突时并列照录、不擅自取舍。
联网抓取使用 anysearch MCP（本项目信任工具）。

**R9 · 伦理提示不可移除。** 「卦象为传统术数文化参考，不构成任何现实决策建议」
的提示必须保留在编排器流程与输出约定中；时间/姓名/报数三技能中关于
「两派约定（立春界/晚子时）」「报数为后人变通」的〔注〕不得删除。

**R10 · Git 纪律。** 提交信息用中文，一个逻辑变更一个提交；推送走 **SSH**
（HTTPS 在维护环境会被重置；本机 `id_ed25519` 已绑定 LuzzyMeow）；
禁止 force push `main`；`.zcode/`、`__pycache__/` 永不入库（.gitignore 已配）。

## 2. 变更流程（按类型）

| 类型 | 触及 | 必做流程 |
|------|------|----------|
| **A · 引擎/算法** | engine.py / lunarcal.py 逻辑 | ① 先在 `evals/evals.json` **新增**用例锁定新行为 → ② 实现 → ③ §1 R5 三命令全过 → ④ 更新 README 验证矩阵/示例输出 → ⑤ 版本号 MINOR+1 |
| **B · 文档/技能** | SKILL.md / README / sources.md | ① 示例中的卦例数字用引擎实跑核对 → ② SKILL 行数 ≤500、frontmatter 合规 → ③ integrity_check 全过 → ④ 文档笔误类 PATCH，流程变化 MINOR |
| **C · 经典文本** | references/ 原文 | ① anysearch 联网取第二源 → ② 逐条人工裁决（径改/补脱/存异文）→ ③ 校勘记逐条记录 → ④ 用「§3 句验」思路抽验 → ⑤ R5 全过 |
| **D · 历法数据** | LUNAR_INFO / STERM_INFO | ① 任何改动后 `lunarcal.py --selftest` 34 锚点必须全过 → ② 新增锚点时先联网核实（HKO/万年历/权威媒体）再写入 |

**版本号**：`MAJOR.MINOR.PATCH`。输出格式不兼容 → MAJOR；算法/规则变化 → MINOR
（必须伴随新评测用例）；笔误修正 → PATCH。四处版本必须同步：
四个 SKILL.md 的 `metadata.version`、`evals/evals.json` 的 `版本`、README 徽章 ——
`integrity_check.py` 会强制校验，漏改即失败。纯新增文档（如本文件）可不 bump。

**新增子技能**：建 `meihua-<名>/SKILL.md`（frontmatter 含 `parent: luzzy-skill-meihuayishu`）→
在编排器路由表加一行 → 在 README 架构图与技能表登记 → 为其行为补评测用例。

## 3. 验证命令速查

```bash
python3 evals/integrity_check.py    # 文件齐备 / SKILL≤500行 / name=目录名 / 四处版本一致 /
                                    # gua_index 64项唯一·卦画连续·爻位↔上下卦交叉一致 / 引文抽验
python3 evals/run.py                # 回归评测（原书占例 + 示例回归 + 边界 + 历法）
python3 lunarcal.py --selftest      # 历法 34 锚点
python3 lunarcal.py 2026 8 30 10 0  # 任取日期端到端冒烟
python3 engine.py time 5 12 17 9    # 观梅占复现（应输出 泽火革·初爻动·变咸·互乾巽）
```

Windows 注意：`python3` 可能不在 PATH，用 `python`；Git Bash 每条命令前的
`ln/mtab` 报错是 cygwin 环境噪音，可忽略。

**原文句验**（C 类变更自用）：对每处改动，取维基文库原句（去标点、剔〔校注/补〕、
干→乾/馀→余归一）检查包含于我方文件；未命中即差异，逐条裁决为
「径改 / 补脱 / 两本异文存录」三类之一并留痕。

## 4. 联网查证规范

1. **工具**：一律用 anysearch MCP（extract / search / batch_search）；其 extract 对
   raw 文本类 URL 无效，对 HTML 页（ctext、wikisource、gist、汉典）有效。
2. **裁决优先级**：ctext 武英殿本（底本）＞ 维基文库 ＞ 其他全文页/百科/论坛。
   「另一个全文页」与底本不符时（实例：高岛页归妹六五误标九五），**以底本为准**。
3. **可靠 URL**：周易逐卦 `https://ctext.org/book-of-changes/{slug}/zhs`（slug 见
   gua_index）；梅花 `https://zh.wikisource.org/zh-hans/梅花易數/卷一`（卷二/三同理）；
   笔画 `https://www.zdic.net/hans/<字>`；农历 `https://wannianrili.bmcx.com/` 与
   HKO 对照表。完整梯次见 `references/sources.md`（新增源必须先实测再登记）。
4. **已知源缺陷**：维基文库简体页有 乾→干 自动转换（核卦名用繁体页）；ctext /zhs
   会把 寘→置、菑→灾、愬→诉 等做简转——照录底本时注意区分「原文如此」与「简转产物」。

## 5. 已知陷阱清单（前人真实踩过的坑）

| # | 陷阱 | 后果 | 正确做法 |
|---|------|------|----------|
| 1 | 体用方向记反 | 文档示例体/用颠倒 | 动爻所在为**用**；1–3 爻动用=内卦，4–6 爻动用=外卦 |
| 2 | 先天数 7 当「兑」 | 示例错卦（7=艮，2=兑） | 默诵：乾一兑二离三震四巽五坎六艮七坤八 |
| 3 | 康熙笔画混入字占 | 笔画数错（王4、氵3、阝2、艹3） | 字占只认**实际书写笔画**；康熙画数仅姓名学五格用 |
| 4 | 手算余数写进文档 | 与引擎脱节 | 一律引擎实跑，把真实输出誊进文档 |
| 5 | 改引擎输出格式 | evals 中文子串断言连锁失败 | 输出格式变更=MAJOR，同步 evals.json 与 README 示例 |
| 6 | 删评测或放宽断言 | 回归失去意义 | 用例只增不减（见 R5） |
| 7 | HTTPS 推送 | Connection reset | 用 SSH（R10） |
| 8 | 引擎硬编码数据路径 | 换目录即崩 | 一律相对 `__file__` 解析 |
| 9 | 动经典文本不留痕 | 校勘链断裂 | 三类操作+校勘记（R2/R3） |
| 10 | 引用未验证网页文字 | 引文不可靠 | 双源+URL 标注（R8） |

## 6. 已知限制与待办（诚实清单，勿删）

- 历法数据 1900–1950 年公开锚点较少，极早年结果建议联网万年历复核（免责声明在
  lunarcal.py 文件头与 README，**不得移除**）。
- 互卦口诀「乾坤无互，互其变卦」（卷一）未做特殊分支——乾/坤重卦目前按常规取互
  （仍得乾/坤）。如要实现该口诀，先在 evals 增补用例再动引擎（A 类流程）。
- 字占「四字以上以平仄声调取数」为原文旧例，入声需古音判断，未入引擎；按 name
  skill 约定由 Agent 手工处理并注明「声调法系原文旧例」。
- 时间起卦 B 法（节气月）在 lunarcal 输出层已支持，端到端评测未单独覆盖；
  如改动 `jieqi_yue()` 须补用例。
