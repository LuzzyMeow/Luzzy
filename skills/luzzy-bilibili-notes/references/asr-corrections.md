# 字幕重组时的识别错误处理

B 站 AI 字幕由语音识别生成，中文技术内容里高频出现同音误写。本文件给出判定与处置规则。

## 判定优先级

1. **技术专名优先**：`deep sick` / `DSSH` / `DH` → DeepSeek / DSH；`cloud code` → Claude Code；
   `OBSIDIUM` → Obsidian；`GITHUB` → GitHub；`ANTHROPIC` → Anthropic；
   `pad`（语境为开源 Agent 底座作者）→ 常见为某框架名，**不确定则列入存疑**
2. **数字与英文大小写**：`sub agent` → subagent；`1亿` / `1 亿` 统一为 `1 亿`
3. **人名**：`杰弗里辛顿` → Geoffrey Hinton；中文音译名与英文原名并存时，
   正文用中文音译 + 首次出现时括注英文
4. **普通词汇**：`良盛时期` → 鼎盛时期（结合上下文显然成立才改）

## 三类处置

| 情形 | 处置 |
|---|---|
| 结合上下文**唯一确定** | 直接修正，记入笔记「已修正的明显识别错误」 |
| 上下文**指向明确但不唯一** | 保留原词，列入「存疑待核」 |
| **无法判断**（专有名词、缩写、项目代号） | 原样保留，列入「存疑待核」，**不做推测性改写** |

## 硬规则

- **不编造**：不确定的词不要「修正」成看起来合理的词——这会让笔记产生虚假的具体性
- **不漏记**：凡改动过的地方都要在「整理说明」里留痕，形成可核对的链条
- **不改原意**：修正只针对明显的同音误写，不得借机改写说话人的观点或语气
- **口语与方言不修**：说话风格属内容的一部分，只删填充词，不「改得文雅」
- **数字与结论不代改**：听起来像数字但不确定的（`飞豹五`、`小南梁`），一律进存疑

## 为什么这么严

AI 字幕的错误率在 2%–10% 之间浮动，而技术视频里**恰好是同音专名最密集的场景**。
一旦把不确定的词「修」成确定的词，读者无法分辨哪些是原始内容、哪些是模型的猜测，
笔记就失去了参考价值。留一个「存疑待核」段，读者可以自行回到视频核对。
