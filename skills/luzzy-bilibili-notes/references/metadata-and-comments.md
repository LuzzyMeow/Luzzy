# 元数据与评论抓取：接口契约与实测陷阱

抓取脚本：[scripts/fetch_video_info.py](../scripts/fetch_video_info.py)。
本文件记录**为什么脚本要那么写**——四条实测陷阱与完整性判据。

## 接口清单

| 用途 | 端点 | 关键参数 |
|---|---|---|
| 视频元数据 | `/x/web-interface/view` | `bvid` |
| 分 P 目录 | `/x/player/pagelist` | `bvid` |
| 一级评论（老） | `/x/v2/reply` | `oid`(=aid) `type=1` `pn` `sort=2` `ps=20` |
| 一级评论（新） | `/x/v2/reply/main` | `oid` `type=1` `mode=3` `next` |
| 二级回复 | `/x/v2/reply/reply` | `oid` `type=1` `root`(=一级 rpid) `ps` `pn` |

`type=1` 是视频。`sort=2` 与 `mode=3` 均为热门序。

## 陷阱一：一级评论要合并两个接口才全

新接口返回**较少**的一级评论，只用一个会漏。实测同一视频：

| 接口 | 一级评论 |
|---|---|
| 老接口 `/x/v2/reply` | **20 条** |
| 新接口 `/x/v2/reply/main` mode=3 | 19 条 |
| 合并去重后 | **20 条** |

新接口的 `mode=2`（时间序）单独用更差——实测只返回 1 条，不能作为主力。
**做法**：两个接口都翻页，结果按 `rpid` 去重合并。

## 陷阱二：二级回复不在列表里

一级评论只带 `rcount` 计数字段，**正文要另调** `/x/v2/reply/reply`。
这是最容易漏的一步——只翻一级评论的页，会以为「评论就这么几条」。

**验证方法**：逐条比对「声明 rcount」与「实取子回复数」。两者应当逐个相等。
相等而总数仍少于页面计数，就说明差值来自被删除的评论（见陷阱四）。

## 陷阱三：mid 的类型不一致

`member.mid` 是**字符串**，`upper.mid` 是**整数**：

```
data.upper.mid   = 3706979189000407  (int)
member.mid       = "3706979189000407" (str)
```

直接 `==` 比较**永远为 False**，`is_uploader` 标记会全部失效且不报错。
**做法**：两侧都转 `str` 再比。

## 陷阱四：实抓数可能少于声明数

页面与接口的计数（`stat.reply`、`cursor.all_count`）**包含已删除或隐藏的评论**，
但接口不再返回它们的正文。实测差 4 条：

| 项 | 数量 |
|---|---|
| 一级评论 | 20 |
| 二级回复（声明 14，实取 14，逐条相符） | 14 |
| 实抓总计 | **34** |
| 页面/接口声明 | **38** |
| 差值 | 4 |

**这不是抓取遗漏**。逐条核对证明每个 `rcount` 都已取满，缺口只存在于总数层面。
**做法**：如实报告差值，`comments_summary.gap` 记下数字，**不假装取全**。
在笔记里写清「页面显示 N 条，实抓 M 条，差值来自已删除评论」。

## 完整性判据

判定「评论是否取全」看两处，缺一不可：

1. **逐条核对**：每个一级评论的 `rcount` == 实取子回复数
2. **总数核对**：`实抓总数 + gap == 声明数`

两处都通过 → 取全（含「已删除评论造成差值」的取全）。
任何一处不过 → 有真遗漏，回查翻页逻辑。

## 风控处置

风控退出码：`-352` 触发风控、`-412` 请求被拦截、`-509` 超出限制。
HTTP 侧对应 `403` / `412` / `429`。

**触发后停止一切请求**，如实告知用户。禁止：重试、换 IP、换 UA、调整参数对抗。
合规依据（律师函先例与允许范围）见 SKILL.md 的 Compliance Boundary 一节。

请求间隔下限 1.2 秒（脚本内 `REQUEST_INTERVAL`）。这是合规纪律要求的低频，
**不要为了提速调小**。单视频通常 20–40 次请求即可完成。

## 输出结构

脚本产出 JSON，字段如下：

| 字段 | 内容 |
|---|---|
| `video.title` | 视频标题 |
| `video.desc` | 视频简介 |
| `video.uploader` / `uploader_mid` | UP 主名称与 mid |
| `video.duration_seconds` / `part_count` | 总时长、分 P 数 |
| `video.stat` | 播放 / 点赞 / 投币 / 收藏 / 评论 / 弹幕 / 分享 |
| `parts[]` | 分 P 目录：`page` `part` `duration` `cid` |
| `comments[]` | 全部评论，含 `level` 区分 `root` / `child` |
| `comments_summary` | 取抓统计与完整性声明 |

`comments[]` 每条含：`rpid` `parent_rpid` `level` `author` `author_mid`
`is_uploader` `like` `rcount` `ctime_text` `message`。

## 字幕不在本脚本范围

字幕由 yt-dlp 取（见 SKILL.md 的 Workflow 步骤 4），因为它需要处理
cookie 与登录态，与纯 HTTP 接口是两条路径。两者合起来构成完整的四项抓取：
**标题、简介（本脚本）＋ 字幕（yt-dlp）＋ 全部评论（本脚本）**。
