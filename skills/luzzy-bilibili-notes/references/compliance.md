# B 站数据抓取的合规边界

本文件记录边界的事实依据，供 Agent 在用户要求越界时说明理由。

## 事实依据：2026 年的两次维权

| 时间 | 对象 | 结局 |
|---|---|---|
| 2026-01-28 | `SocialSisterYi/bilibili-API-collect`（20.2k star 的 API 逆向文档仓库） | 收到平台委托律所律师函，01-30 归档关停，文档与源码删除 |
| 2026-07-06 | `Nemo2011/bilibili-api`（4.2k star 的 Python SDK，即 `bilibili-api-python`） | 收到上海市弘安律师事务所律师函，永久关停 |

律师函点名主张侵权的具体行为：

- 突破登录态与访问控制
- 绕过反爬风控与**签名鉴权**（WBI）
- 抓取 OGV 番剧与**付费课程**内容
- 采集弹幕并**反查用户真实身份**

依据《民法典》《反不正当竞争法》《网络安全法》。

复刻/镜像仓库（如 `pskdje/bilibili-API-collect`）随后也宣布归档转私有。
以 `bilibili-api-python` 为底层依赖的第三方工具（多个 MCP server）**依赖已死**：
PyPI 旧版本仍可安装，但签名机制一变即失效，且不再有维护。

## 本技能允许的范围

- 公开可见视频的**标题、简介、封面、时长、UP 主**等元数据
- 公开可见视频的 **AI 字幕（`ai-zh`）**
- 公开可见视频的**公开评论**
- 以**用户自己的登录态**访问上述数据
- 低频率、单视频或少量视频的**个人学习与研究用途**

## 本技能禁止的范围

- 批量 / 全站 / 持续抓取
- 绕过 WBI 签名或任何风控机制
- 访问付费、OGV、充电专属内容
- 突破登录态或访问控制
- 下载视频本体（本技能只取字幕与元数据）
- 通过弹幕反查发送者身份
- 把抓到的数据上规模分发或商用

## 越界请求的处置

用户要求上述任一行为时：

1. 明确说明**不做什么**与**依据**（引用上面的律师函事实，不空谈「可能违规」）
2. 给出**合法替代**：官方开放平台 `https://openhome.bilibili.com/` 提供账号授权、
   用户管理、视频管理、数据开放能力，面向创作者授权场景，是最安全的路径
3. 若用户坚持，停在拒绝这一步，交由用户决定是否另寻他途——**不代为执行**

## 频率纪律

即便是允许范围内的抓取，也保持低频率：单视频通常 1–2 次请求即可完成；
连续翻页取评论时容易触发 `-352` / `403` 风控。触发风控后**停止重试**，
不要换 IP、换 UA 或调整签名去对抗。
