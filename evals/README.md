# Luzzy 门评测层

针对「必读清单能否稳定触发」的证据层。两个工具、一份语料：

| 件 | 测什么 | 怎么跑 |
|---|---|---|
| `eval-gate-coverage.py` | **词面覆盖**：§1.1.8 触发口径的关键词面，对 `gate-corpus.json` 里真实任务说法的子串覆盖（各类目 recall） | `python evals/eval-gate-coverage.py`，门槛 ≥80%，低于门槛 exit 1 |
| `check-receipt.py` | **行为痕迹**：一段会话转录里，§1.1.2 读取回执 / §1.1.5 三行分诊有没有落、类目对不对 | `python evals/check-receipt.py <转录> --expected "后端 / 通用编码"`（或 `--triage`） |
| `gate-corpus.json` | 156 条语料：19 个类目 ID 的任务语句 + 3 条并列（multi）+ 10 条分诊触发（triage）+ 10 条闲聊负例（chitchat） | 改 §1.1.8 或新增类目时扩充并重跑覆盖审计 |

## 诚实声明：这层证据的边界

词面审计测的是**关键词表的覆盖盲区**，不是模型行为——它不能证明模型会照 §1.1.1 过门、会落回执。行为证据只有一条来源：**转录测录**。两层合起来才是完整的证据链：静态层在每次改动后立刻跑（秒级、无 Key），行为层按下面的协议定期积累。

## 覆盖审计（静态层）

```bash
python evals/eval-gate-coverage.py            # 全部类目 recall ≥80% 才 exit 0
```

输出四块：各类目 recall 表（含逐条 miss）、跨类目命中（并列属正常，仅提示）、triage / chitchat 误命中（这俩是硬失败——负例被命中说明关键词过宽）、multi 全空（硬失败）。

**改 §1.1.8 触发口径后必跑**；新增第十八类时同步改 `eval-gate-coverage.py` 的 `CANON` 表（语料 ID → 条目名，改条目名也要同步，脚本会报断链）。

### 已记录盲区（2026-09-18 基线）

以下语句是**已知漏报**，作为各目的容忍缺口保留（不硬凑 100%）：

- backend：「我们要选一个 ORM，你对比下 TypeORM 和 Prisma 再定」（「选型」的口语变体「选一个」未覆盖）
- ppt：「帮我做几页发布会风格的页面」（「的」字阻断了「发布会风格页面」）
- html：「做一个静态官网首页」（「静态站」未覆盖「官网」说法）
- planning：「MVP 范围帮我定一下」（范围划定类说法未覆盖）
- academic：「帮我做一个研究计划去申请基金」（「做研究计划」词序变体）
- problem-solving：「想找一套通用的解题方法来练」（插入语「一套」）

补这些盲区时优先**只增不删**地在 §1.1.8 对应条目加同义词，补完重跑；若新关键词导致 chitchat / triage 误命中，说明加宽了，收回来。

## 转录测录协议（行为层）

测「模型真的会停手过门、落回执」的唯一手段：

1. **起一个新会话**（挂 Luzzy 提示词的任意 harness），逐条贴 `gate-corpus.json` 的任务语句——一类目抽 2-3 条即可，分诊语句（triage-*）单独开新会话贴（它们模拟中途接手）
2. **存转录**：把每轮会话导出 / 复制为 markdown，一个语句一份（或一份多段，段间有明确分隔）
3. **核验**：
   ```bash
   python evals/check-receipt.py 转录/backend-02.md --expected "后端 / 通用编码"
   python evals/check-receipt.py 转录/triage-02.md --triage
   ```
4. **统计**：各类目回执落率 = PASS 数 / 抽测数。低于 90% 的类目，对照静态审计排除关键词问题后，属于提示词遵从问题——往 §1.1.1 / §二 第 1 步的复述链路上查

转录文件**不进本仓库**（属本机测试数据），统计结果值得沉淀时写进 `prompt/Luzzy.md` 对应类目或维护备忘。

## 语料维护规则

- **id 前缀 = 类目 ID**，与 `eval-gate-coverage.py` 的 `CANON` 对应；新增类目先加 CANON 再加语料
- **kind 语义**：`task`＝expected 全部命中（并列任务）；`multi`＝expected 至少一个命中（语句层无法分辨的天然歧义，运行时靠分流 / 并列规则）；`triage`＝不应命中任何类目（应走 §1.1.5）；`chitchat`＝不应命中任何类目
- **只收真实说法**：口语到正式各档；不为了凑命中率把语句改写成关键词的复读——语料是考题，不是答案的抄写
- **允许等自然度改写**：改写仅当新说法与原说法同样自然（如「排个期」→「排期」），且不得把漏报改没——漏报要么补关键词、要么记录为盲区，不许靠改语料消失
- 本版语料为编者拟写的近似说法，**薄弱类目**（说法多样性不足，建议补真实母语料）：design-subitem（仅 5 条）、multi（仅 3 条）、全部类目的正式语域（如「为以下需求出具技术方案」类）偏少
